# v540 BPM 检测研究记录

## 结论先行

本轮回合已达到**初期实验目标**：恒速输出一个主 BPM，合成与真实恒速样本不误报变速；阶跃、渐变及两首真实变速歌曲能检出变速。最终 `check.mjs` 的 20 个合成场景、3 个分类器单元测试、4 首真实歌曲全部通过，TypeScript 编译通过。

真实样本的主 BPM 为 Yoko 140.8、Turupeta 180、Nare 145、Carnival 220；Yoko/Turupeta 不报变速，Nare/Carnival 报变速。四首的主恒速区在各自 MP3 时间基准补偿后网格覆盖率均为 100%。

**尚不能直接当作完整自动 timing 功能**：当前实现位于新模块 `src/osu/bpmResearch.ts`，未接入 UI；变速 evidence 是 4 秒分析窗形成的粗略区间，不是精确红线；真实样本只有 4 首且参与阈值研究，需要独立 held-out 集复核。

## 初期目标与验收口径

1. 恒定速度：输出一个 BPM 和一条主 timing 线；严格比较已知 BPM，不再把 2× / 0.5× 当作“数值正确”。
2. 恒定速度：不应误报变速；offset 用原始已知拍点检查网格残差。
3. 变速：先只要求可靠地区分“有真实变速”，再逐步提高分段位置和各段 BPM 精度。
4. 结论必须区分理想点击轨、带干扰合成轨、真实音频；合成通过不代表真实歌曲通过。

## 防止验证方法自证

- 参考拍点由独立合成器事先生成，不能从被测算法的 onset、beats 或 segments 反推。
- BPM 数值、网格、唯一输出、变速误报分别记录；旧版“倍速网格相容即通过”不再作为数值正确证据。
- 合成用例覆盖非整数 BPM、强拍、offbeat、持续音、噪声、抖动、缺拍、breakdown 和相位重置。
- 真实音频与谱面标注已复制到 `fixtures/`，用 Electron/Web Audio 解码到 `decoded/`；不用算法输出当 ground truth。
- Nare 单独区分“谱面只有一条 145 BPM 红线”和“声学 outro 可能真实加速”，不把 mapper 简化当作声学恒速证明。
- 检测失败时分别检查 onset、周期候选、跟拍、最终提炼和测试工具本身。

## 已有实现审计

- 旧管线：`src/osu/bpmDetect.ts`，STFT 频谱通量 → ACF 候选 → Viterbi tempo 曲线 → DP 跟拍 → 分段/恒速提炼。
- 旧测试 v498 的 128、160 理想点击轨通过，但真实用例允许倍速；v499 的真实 Carnival 变速只打印、不强制检出。
- 旧实现用最长原始段作为恒速主段，并依赖跟拍结果；真实 Carnival 的局部变速信息在跟拍后已经丢失。
- 本轮保留旧管线的全局周期精度，但将**输出倍程选择、offset 相位、局部变速分类**拆成独立研究模块，不再仅合并旧碎段。

## 实验日志

### E0：旧合成基线与验收口径修正

- 旧 `v498/tests.ts` 输出 128=128、160=160，20 段变速网格 77.9%。
- 扩展矩阵见 `baseline-results-e1.jsonl`：带 offbeat 的 128 / 137.5 / 140.8 / 174 / 180 均返回 2×；360 返回 80 且只有 15 个跟踪拍点。
- **验证方法修正**：等间隔 offbeat 使 128 与 256 都有真实声学周期，不能仅凭网格断言 256 是 DSP 错误。将“周期估计”和“倍程/节拍层级选择”分开。
- 旧管线对阶跃 128→173、渐变 120→180 有变速敏感性，但主 BPM 分别变成 346 / 343.3，不能据此认定分段准确。

### E1：非整数 BPM 假设被否定

- 无 offbeat 的 128、137.5、140.8、174、180、360 全部准确到 0.1 BPM，offset 中位误差约 3 ms，见 `strong-results.jsonl`。
- 结论：H1“非整数 BPM 本身受 lag 量化导致测不准”不成立；优先研究真实 onset、倍程和变速路径。

### 真实旧基线

|---|---:|---:|---|---|
| Yoko | 140.8001 | 281.6 | 1 线、无变速 | 周期网格对，但数值倍程不符严格目标 |
| Turupeta | 180 | 360 | 1 线、无变速 | 另有约 30 ms 时间基准偏差 |
| Nare | 145 | 290 | 1 线、无变速 | outro 声学加速未报 |

### 解码与诊断工具自身的两轮错误

1. 局部诊断最初全部返回空，先怀疑搜索范围；随后发现 `onsetEnvelope(pcm)` 漏传采样率，`hopMs=NaN`，JSON 将 NaN 显示为 null。修正为 11025 Hz 后才得到局部候选。空候选不能未经输入检查就解释为“无节拍”。
2. MP3 头检查：Yoko 无 Xing/Info/VBRI；Turupeta、Nare、Carnival 有 Xing。对后者仅在 fixture 验收中补偿 25 ms 后，主恒速区网格均达到 100%。这证明时间基准必须独立记录；**当前研究 API 尚未把文件头延迟元数据接入应用**。

### E2：直接局部周期，而非旧跟拍分段

- 使用 4 秒窗、1 秒步长，直接对 onset 做 ACF 候选；主 BPM 先归一到显式 60–240 范围。
- Carnival 在 190–200 秒连续偏离 220，Nare 在约 210 秒出现 173.7；说明变速信息在 onset/局部周期层存在，H3 得到支持。
- 第一版“偏离 ≥8% + support ≥0.045 + 局部/全局支撑比 ≥1.15 + 连续 3 窗”能报真实变速，但 Yoko、Turupeta 各出现一个误报区。

### E3/E4：主网格阈值无效且会误杀

- 加入主 BPM 1/8、1/6 网格覆盖率后，真假窗覆盖率都约 0.7–0.8，无法区分。
- 阈值 0.8 消除了部分误报，却也滤掉 Nare 的真实 outro 加速。
- 结论：该网格门槛在当前 onset 峰提取方式下无效，最终移除；保留覆盖率仅作诊断字段。

### E5：连续性约束达到真实样本阶段目标

- 误报候选会在 60→82→61、80→102→199 间随机跳变；真实阶跃/渐变具有连续局部周期。
- 最终要求连续至少 3 窗，且相邻局部 BPM 变化 ≤10%；渐变速每秒平滑变化也可通过。
- 结果：Yoko/Turupeta 0 误报；Nare 检出 204684–216671 ms、173.713 BPM；Carnival 检出多个变速区。
- Carnival 的 evidence 含前奏和粗略慢速窗，**只证明“有变速”，不证明每段边界和 BPM 都正确**。

### E6–E10：offset 相位实验与测试修正

1. BPM 折叠后沿用旧 offset 会落在弱 offbeat，合成误差约半拍；需要重选相位。
2. 第一版只在 BPM 折叠时重选，但部分旧输出已是 128 BPM、offset 仍在 offbeat，条件不会触发。
3. 改为比较四个 1/4 拍相位后，合成改善，却把真实 Yoko 的 syncopation 当强拍，真实网格从 100% 退步。
4. 最终只比较倍程折叠产生的相位；未折叠时只复核两个半拍相位。直接按候选网格读取原始 PCM 瞬态峰值，不依赖旧拍点是否覆盖强拍。
5. 期间发现评分窗 `0.012 / 1000 * sampleRate` 时间单位错误，实际只有 1 个采样点；修为 `0.012 * sampleRate` 后才形成有效 12 ms 峰值窗。
6. “连续渐变应报”单测最初首点只偏离 7.1%，低于既定 8% 门槛，属于测试数据错误；改成三个均满足门槛且连续变化的点，没有放宽算法。
7. 300/360 BPM 等强度 click 降倍后，隔拍相位没有声学唯一解；这两例只验收显式 BPM 归一，不宣称恢复真实拍号或强拍相位。

## 最终研究方案

1. **输入与声道**：沿用旧管线逐声道检测并选择结果；保存 onset envelope。
2. **全局周期**：沿用旧管线得到 raw BPM 与初始 offset，避免本轮同时重写所有 DSP 层。
3. **唯一主 BPM**：`normalizePrimaryBpm` 按 2 的幂折叠到显式 60–240 BPM；只输出一个数，不并列多个候选。
4. **offset 相位**：`selectPrimaryOffset` 只比较折叠产生的候选相位，未折叠时比较原相位/半拍相位；以原 PCM 12 ms 瞬态峰值评分。
5. **局部变速证据**：4 秒窗、1 秒步长；局部候选同样归一；全局支撑取半速/原速/倍速最大值。
6. **逐窗标记**：与主 BPM 偏离 ≥8%、support ≥0.045、局部/全局支撑比 ≥1.15、有效 onset 峰 ≥6。
7. **连续确认**：至少 3 个相邻秒窗，相邻局部 BPM 变化 ≤10%；输出 `variable` 和粗略 evidence，不直接生成红线。

## 最终验收结果

- `synth-hypothesis.ts`：60–220 的 9 个整数/非整数恒速；offbeat、强拍、噪声+持续音、抖动+缺拍、稀疏 breakdown、相位重置；300/360 显式归一；阶跃、渐变、短阶跃，全部通过。
- 常规恒速合成 offset 中位误差 0–4 ms，且全部不误报变速。
- 分类器单元测试：随机跳变不报，稳定新周期和连续渐变应报。
- `real-acceptance.ts`：四首主 BPM 误差均 ≤0.2%，声学变速分类符合预期；主恒速区在 fixture 解码补偿后网格均 100%。
- `check.mjs` 输出 `VERIFIER_V540_ALL_TESTS_PASSED`；`npx tsc -b` 通过。

## 猜想结论汇总

- H1（非整数 BPM 本身不准）：**否定**。
- H2（噪声/持续音一定先破坏 onset）：**未作为普遍根因证实**；合成干扰通过，真实 onset 仍需更多样本。
- H3（变速应独立于旧跟拍分段）：**支持**，局部直接周期能检出旧管线漏掉的真实变速。
- H4（不能依赖全曲 3% 拍点过滤）：**支持**，本轮改用局部连续证据，但短于约 3 秒的变化仍可能漏检。

## 未解决问题与下一轮方案

1. **独立验证集不足**：当前 4 首参与研究，下一轮先冻结阈值，再选至少 20 首未参与调参的恒速/变速歌曲，报告 false-positive/false-negative，而不是继续在这 4 首上调参。
2. **倍程先验不是拍号识别**：60–240 是产品先验；300→150、360→180 是显式折叠。若要保留高 BPM，需要用户范围或节拍层级/强拍模型。
3. **变速区间粗糙**：evidence 起止受 4 秒窗影响，Carnival 还有可疑前奏证据。下一轮用 1–2 秒多尺度窗和变点检测精修边界，再拟合各段周期/相位。
4. **短变速与逐拍变速**：连续 3 秒窗会漏掉更短变化；需要单独的“高置信短段”路径，不能与防误报规则混为一谈。
5. **解码延迟未接入**：25 ms 是这些 MP3 fixture 的验证补偿，不是所有文件的通用常数。应用应传递解码器/文件头时间基准，而非在 DSP 中硬减 25 ms。
6. **UI 未接线**：本轮只新增研究 API 和验证器，不改变现有 BPM 对话框行为。
