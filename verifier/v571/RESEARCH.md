# v571 / E12 诊断：full 峰可恢复性与密集峰空对照

## 结论

**full 表征在标注音头附近几乎总能提供峰，但 oracle 上限存在严重选择自由度，不能直接解释为可恢复准确率。** 对 sample-032 / sample-002 的 E10 错误，实际音头 ±5 ms 内有 full 峰的权重比例为 **92.9699%**，把全部这些物件视为修复会得到 **97.9016%** 的 oracle 上限；然而 ±50 ms 错误中心也有 **90.5451%** 的相同命中率，二者只差 **2.4248 个百分点**。

因此 H1/H2 只在数学 oracle 口径下成立，不能据此宣称新算法可达到 97.9016%。真正值得测试的是**不使用当前物件标注的 corrected-target 重匹配**，并必须用实际 ±5 ms 主指标、fixed/broken 和 no_clear 守卫评价。

- H1“至少 50% 的 E10 错误权重附近存在正确 full 峰”：**算术上成立**，实际 92.9699%。
- H2“全部 oracle 修复可使总体达到 80%”：**算术上成立**，上限 97.9016%；但空对照说明该上限很宽松。
- H3“90 个旧候选 parity、全部诊断和空对照可独立重建”：**成立**。
- 未修改生产 BPM 代码，未读取、解码或评估六首独立确认歌曲。

| sample-044 | 11,499 | 30 / 30 完全一致 |
| sample-032 | 30,982 | 30 / 30 完全一致 |

90 个 `fullResidualMs` 均与 v558 精确相等。独立复验又从导出峰暴力搜索旧 target ±10 ms，重建了全部 90 个残差，而不是只相信导出脚本的自检。

## 主诊断口径

分析 sample-032 / sample-002 的 29 个 clear + approximate 物件，人口权重 1717.8；其中 13 个 E10 错误物件的权重为 532.0。在标注音头 ±20 ms 内取最近 full 峰，互斥分为：旧目标已选正确峰、窗口内正确峰但选错、正确峰在旧窗口外、附近有峰但超过 ±5 ms、±20 ms 内无峰。

| 分类 | 物件数 | 总权重 | E10 错误权重 | 占错误权重 |
|---|---:|---:|---:|---:|
| 旧目标已选正确峰 | 0 | 0 | 0 | 0% |
| 窗口内正确峰但选错 | 0 | 0 | 0 | 0% |
| 正确峰在旧窗口外 | 27 | 1680.4 | **494.6** | **92.9699%** |
| 附近有峰但超过 ±5 ms | 2 | 37.4 | 37.4 | 7.0301% |
| ±20 ms 内无 full 峰 | 0 | 0 | 0 | 0% |

所有最近正确峰都在旧 target ±10 ms 外，说明旧 target 与标注中心存在系统性偏移；E5 通过反折中位数平移旧候选，已经修复其中一部分。剩余错误不能简单归因于 full 缺峰。

## oracle 上限与为什么它不够

当前 E10 三首有音正确权重为 1296.9778 / 1829.9778，即 **70.8740%**。E10 错误且附近存在正确 full 峰的权重为 494.6：

```text
(1296.9778 + 494.6) / 1829.9778 = 97.9016%
```

这个计算允许使用人工标注中心选峰，不计算假峰代价，也没有给出部署时如何选择该峰。因此它不是候选算法成绩。

## ±50 ms 移位空对照

为检验密集峰是否造成“任何时间都能找到峰”，额外冻结了诊断审计用的 ±50 ms 空对照；它不是候选算法，也不改变主实验的 H1/H2 定义。

| 中心 | 全部有音 ±5 ms 有峰率 | E10 错误物件 ±5 ms 有峰率 |
|---|---:|---:|
| 实际音头 | **97.8228%** | **92.9699%** |
| 实际音头 -50 ms | 79.2584% | 88.1203% |
| 实际音头 +50 ms | 65.9157% | 92.9699% |
| 两种移位合并 | 72.5870% | **90.5451%** |

对于当前错误物件，错误时间中心的峰命中率与实际中心几乎相同。这直接削弱了“oracle 上限接近 98%，所以很容易修复”的猜想。full 峰密度使 oracle 具有很大 trivial selection freedom，必须测试真实的无当前标签选峰规则。

## 独立复验

`check-results.py` 使用全数组暴力最近峰，独立复算 90 行 parity、29 行主诊断、58 行空对照、两份 CSV、互斥分类、人口权重、oracle 上限和空对照覆盖率。最终输出 `V571_RESULT_VALIDATION_PASSED`，H1=true、H2=true、H3=true，同时明确记录 oracle 不构成部署准确率声明。

所有标签仍是 provisional 视觉盲标。移位空对照只用于审计本次 oracle 的证据强度，不是音乐结构模型，也不是新系统误报率。

## 下一实验

冻结一个 corrected-target 重匹配实验：

1. 使用同曲反折 E5 `correctionMs`，令 corrected center = 旧 target - correctionMs。
2. 在 corrected center ±10 ms 内重新选择最近 full 峰，而不是只平移旧 target 附近已选的峰。
3. 候选缺失计不正确；与 E10 比较人口加权 clear + approximate ±5 ms 正确率、fixed/broken 和 no_clear 输出率。
4. 不扫描窗口、阈值或单曲规则，不按 sampleId 选方法。

该实验只使用反折校准和部署时可获得的 full 峰，能直接检验“平移搜索中心后重新选峰”是否比“平移旧候选”更有效。
