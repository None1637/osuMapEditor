# v549：80% 每音测量目标的瓶颈与可达性诊断

## 结论先行

目标按“**物件音头测量误差 ≤5 ms 的命中率达到 80%**”推进。本轮没有达成该目标，也没有把弱标签口径下刷过 80% 的数字当成完成。

- v548 top2 / 短程 DP 在 20 首、17,149 个物件上的当前结果为 **10,876/17,149（63.42%）**。
- 当前 full-band 峰在 ±10 ms 内只匹配 **13,351/17,149（77.85%）**，因此现有评估口径下，即使已匹配音全部达到 5 ms，也不足 80%。
- 保持 20 ms 峰抑制，事后为每条红线选择最优相位，全曲上限也只有 **11,321/17,149（66.02%）**；相对实际只增加 445 个。密集段事后段相位上限为 **193/254（75.98%）**，同样不足 80%。
- 把峰抑制从 20 ms 降到 5 ms，弱标签一致率可达到 **86.55%**；完全不抑制则达到 **99.78%**。这证明“增加候选峰”可以轻易刷过目标，却也使该验证口径失去区分真音头和偶然邻近峰的能力。
- **所以 80% 的正式验收必须加入独立 onset 精标。** 本轮只确定瓶颈，不修改生产检测参数。

## 1. 诊断设计

固定使用 v548 的 20 首及其 top2 / DP 交叉拟合相位，不重新拟合：

1. 复现当前 20 ms 抑制、0.02 阈值的结果，确认诊断脚本与 v548 完全一致。
2. 比较峰抑制 20 / 10 / 5 / 0 ms，以及阈值 0.02 / 0.01 / 0.005。
3. `segmentOracle`：在正在评分的同一批物件上，事后给每条红线选最优相位；只是段相位模型的上限，不是可部署预测器。
4. `noteOracle`：每个音独立事后选择相位，只要求 ±35 ms 内存在任意峰；只是候选峰覆盖上限，更不是精度。
5. 所有未匹配物件保留在分母中。

## 2. 全曲结果

| 峰设置 | 当前相位 ±5 ms | 全局基线 ±5 ms | 每音事后覆盖上限 |
|---|---:|---:|---:|
| 抑制 20 ms / 阈值 0.02（当前） | 10,876/17,149（63.42%） | 10,812（63.05%） | 17,048（99.41%） |
| 抑制 10 ms / 阈值 0.02 | 12,767（74.45%） | 12,765（74.44%） | 17,148（99.99%） |
| 抑制 5 ms / 阈值 0.02 | 14,842（86.55%） | 14,905（86.91%） | 17,148（99.99%） |
| 抑制 0 ms / 阈值 0.02 | 17,112（99.78%） | 17,117（99.81%） | 17,148（99.99%） |
| 抑制 10 ms / 阈值 0.01 | 12,768（74.45%） | 12,765（74.44%） | 17,148（99.99%） |
| 抑制 5 ms / 阈值 0.01 | 14,845（86.56%） | 14,909（86.94%） | 17,148（99.99%） |
| 抑制 10 ms / 阈值 0.005 | 12,768（74.45%） | 12,765（74.44%） | 17,149（100%） |
| 抑制 5 ms / 阈值 0.005 | 14,847（86.58%） | 14,911（86.95%） | 17,149（100%） |

阈值变化几乎没有影响，峰抑制是主导变量。5 ms 设置下，全局基线还高于逐段精修 63 个物件，因此不能把提升归因于 v548 相位模型。

当前 20 ms 设置的两个事后上限：

- 每音自由选相位：17,048/17,149（99.41%）。这仅说明几乎任何物件附近都能找到某种谱通量峰，不能证明峰对应该物件。
- 每红线共享一个事后最优相位：11,321/17,149（66.02%）。这才接近当前“已知红线、唯一段相位”模型的候选上限，仍远低于 80%。

## 4. 猜想与验证

### H1：只要继续优化段相位，就能达到 80%

**否决。** 当前 20 ms 峰设置下，即使使用评分物件事后选择每条红线的相位，也只有 66.02%。稳定段的主要问题不是当前相位搜索算法不够优，而是候选峰/评估模型本身。

### H2：密集段同时存在相位估计不足

**支持，但仍不能达到目标。** 密集段当前为 125/254，段相位 oracle 为 193/254，差距较大；然而 oracle 也只有 75.98%，所以仅优化 DP 仍不够。

### H3：5 ms 峰抑制超过 80%，说明真实精度已达标

**否决。** 不抑制可得到 99.78%，且每音事后覆盖率接近 100%。候选峰越密，物件时间 ±5 ms 内偶然碰峰的概率越高；这是典型的验证口径被算法利用。没有独立 onset 真值时，不能选择 5 ms 参数并宣称成功。

### H4：当前 77.85% 匹配覆盖率就是“80% 物件有音”的直接观测

**不能直接这样解释。** 匹配既可能漏掉真实音头，也可能把无清晰音头物件偶然匹配到邻近峰。两者方向相反，77.85% 不是有音比例的无偏估计。

## 5. 验证过程自身的纠错

本轮两次脚本错误均已修正并重跑，没有混入结论：

1. 初次调用 `onsetEnvelope` 时未补充 `3 × win / 4` 时间偏置，峰时间变为 NaN，所有指标为 0；发现后与 v548 当前结果逐项对照修复。
2. 初版 `noteOracle` 只扩大找峰半径，却仍按原物件时间计算 ±5 ms，导致其 within5 错等于全局基线；修正为“每音事后相位可把找到峰的残差改为 0”。

最终脚本的当前配置已逐样本复现 v548 top2 / DP 的 10,876/17,149，避免把时间轴或指标实现错误当成算法结论。

## 6. 下一轮的独立精标设计

在 003、042、095 上分层抽取物件，人工/波形独立标记 `actualOnsetMs` 或 `no_clear_onset`：

- 当前 20 ms 与 5 ms 设置都命中的物件；
- 仅 5 ms 设置命中的物件；
- 两种设置都未命中的物件。

每层使用固定哈希抽样并保留层权重，避免只听算法喜欢的例子。精标时不向标注过程展示候选相位答案。随后分别报告：

1. 对有清晰 onset 物件的 ≤5 ms 精度；
2. 对全部物件的 ≤5 ms 精度及 `no_clear_onset` 比例；
3. 20 ms 与 5 ms 候选的混淆矩阵；
4. 按原层权重的总体估计，而非只报告过采样后的微合计。

只有独立精标也达到 80%，才把该目标标为完成。
