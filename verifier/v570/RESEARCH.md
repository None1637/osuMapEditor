# v570 / E11 诊断：旧目标窗口还是 DDC 缺峰？

## 结论

**两首高权重歌曲当前的主要瓶颈是 DDC 缺峰，不是旧目标窗口。** 在 sample-032 / sample-002 的 E10 错误人口权重 532.0 中，**524.4（98.5714%）在标注音头 ±20 ms 内没有任何 DDC 官方峰**。旧窗口外虽有 2 个 ±5 ms 正确峰，但它们对应物件已被 E5 测对；对当前 E10 错误的可修复权重为 **0**。

- H1“窗口外正确峰至少占两首 E10 错误权重的 20%”：**不成立**，实际为 **0%**。
- H2“只恢复窗口外正确峰不能达到总体 80%”：**成立**；上限仍是当前 **70.8740%**。
- H3“所有物件互斥分类且结果可独立重建”：**成立**。
- 本轮只是 oracle 失败归因，不是新系统成绩；未修改生产 BPM 代码，未重新推理，未触碰六首独立确认歌曲。

## 冻结诊断口径

只分析 sample-032 / sample-002 的 clear + approximate 物件，共 **29 个、人口权重 1717.8**。使用冻结 DDC 官方帧峰，在标注音头 ±20 ms 内取最近峰，并按以下优先级互斥分类：

1. `correctPeakSelectedByOldTarget`：最近峰距标注不超过 5 ms，且就是旧 target ±10 ms 已选中的峰。
2. `correctPeakReachableButNotSelected`：正确峰在旧窗口内，但旧规则选了另一个峰。
3. `correctPeakOutsideOldTargetWindow`：正确峰在旧窗口外。
4. `nearbyPeakButOutside5ms`：±20 ms 内有峰，但最近峰距标注超过 5 ms。
5. `noOfficialPeakWithin20ms`：标注音头 ±20 ms 内没有任何官方峰。

选择官方峰是因为 v560 的 oracle 输出中，官方帧量化 ±5 ms 表现优于抛物线插值；两种表示共享相同峰索引。标注中心只用于诊断上限，不参与任何生产候选。

## oracle 可修复上限

当前三首总体 E10 正确权重为 1296.9778 / 1829.9778，即 **70.8740%**。

- 只把“E10 错误且正确峰在旧窗口外”的物件视为修复：新增权重 **0**，上限 **70.8740%**。
- 把三个“存在 ±5 ms 正确峰”类别中的全部 E10 错误都视为修复：新增权重仍为 **0**，上限 **70.8740%**。

这不表示 E5 已覆盖所有可听音，而表示**当前冻结 DDC 峰集合没有可为这些 E10 错误提供 ±5 ms 正确时间的峰**。继续修 target、匹配窗口或 DDC 校准则无法解决这一集合层面的缺失。

## 验证与失败记录

`check-results.py` 不使用诊断脚本的 searchsorted 实现，而是对冻结峰数组做全数组暴力最近峰搜索，独立重建 29 行分类、CSV、分歌曲/合并权重、互斥分区、oracle 上限和猜想。最终输出 `V570_RESULT_VALIDATION_PASSED`，H1=false、H2=true、H3=true。

首次诊断在输出前因预设“两首有音物件共 34 个”断言失败；实际为 sample-032 17 个、sample-002 12 个，共 29 个。已只修正结构断言和浮点权重容差，分类、窗口和峰搜索规则未改。

所有标签仍是 provisional 视觉盲标。±20 ms 无峰只适用于当前冻结 DDC Challenge 模型、阈值和官方峰集合，不能推广为“音频没有 onset”。
